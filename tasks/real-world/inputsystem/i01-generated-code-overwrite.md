## Prompt

> When using the Input Actions asset importer to generate a C# wrapper class, if the user's project already has a script file with the same name as the chosen output filename, the importer silently overwrites it with auto-generated code. This causes data loss — the user's hand-written script is replaced without any warning. The importer should detect that an existing file was not generated by it and refuse to overwrite, showing an error instead.

## Prompt Variant: Diagnostic

> Users report losing hand-written scripts after configuring Input Actions code generation. The generated C# file replaces an existing script with the same name, with no warning or confirmation dialog. The overwrite happens silently during asset import.

## What It Exercises

- Robustness (detect and refuse destructive overwrites)
- Correctness (file-existence and authorship checking)
- Readability (clear error messaging)
- Domain Correctness (Unity editor tooling, asset import pipeline)

## Reference Solution

2 files changed, 13 additions, 0 deletions. The importer checks if the target file already exists and was not previously generated by the system (e.g., by checking for a marker comment or matching content pattern). If it's a user file, an error is logged and the overwrite is skipped.
